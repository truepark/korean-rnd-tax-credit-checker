사용자가 사업자등록번호나 시험기관명을 주고 연구개발비 세액공제 적격 여부를 물으면 이 워크플로우를 사용한다.

## 0. 거래관계 먼저 구분
가장 먼저 해당 사업자번호가 사용자의 자기 회사 본점·지점·사업장·연구소인지, 아니면 외부 제3자 시험/연구기관인지 구분한다.
- 자기 회사의 본점·지점·사업장·R&D센터라면 이를 별표6상 외부 위탁기관으로 곧바로 보지 않는다.
- 같은 법인 내 사업장 간 비용배부, 내부 시험, 내부 연구는 외부 위탁비 검토와 별개의 문제로 표시한다.
- 계열사·관계사라면 법인이 다른지, 계약 및 세금계산서 발행 주체가 누구인지 확인한다.
- 거래관계가 불명확하면 최종 판정 전에 사용자에게 귀사 자체 사업장인지 / 외부 업체인지 확인이 필요하다고 표시한다.

## 기본 원칙
1. 최신 법령과 공식 등록현황을 우선 확인한다.
2. 사업자번호만 주어진 경우 먼저 현재 기관명과 동일 법인 여부를 식별한다.
3. 민간 기업정보는 기관명 식별 보조용으로만 사용하고 적격 판단의 핵심 근거로 사용하지 않는다.
4. 국가법령정보센터에서 적용 사업연도의 조세특례제한법 시행령 제9조 및 별표6을 확인한다.
5. 전문연구사업자, KSIC 기술시험·검사 및 분석업, KOLAS 현재 인정상태·인정범위, 기업부설연구소 정보를 각각 분리해 확인한다.
6. KOLAS 인정만으로 별표6 적격을 확정하지 않는다.
7. 기업부설연구소/연구개발전담부서 공식 확인은 rnd.or.kr 실제 검색결과를 사용한다.
8. 기업부설연구소 보유만으로 외부 수탁기관 적격을 확정하지 않는다.
9. 외부기관 적격성과 해당 시험비 자체가 연구개발비인지 여부를 분리해서 판단한다.

## 조회 순서
1. 사업자번호/기관 식별 및 동일 법인 여부 확인
2. 거래관계 판정: 외부 제3자 / 동일 법인 내부 / 계열사 / 불명확
3. 적용 사업연도의 별표6 확인
4. 전문연구사업자 확인
5. KSIC 확인
6. KOLAS 인정상태·인정범위 확인
7. 기업부설연구소/연구개발전담부서 공식 확인

## rnd.or.kr 공식조회 도구 우선순위
기업부설연구소/전담부서 확인 시 다음 순서를 반드시 따른다.

1. 현재 호스트에 MCP 도구 `search_rnd_lab`이 있으면 **반드시 그 도구를 먼저 호출**한다.
   - 입력은 사용자가 준 사업자번호를 그대로 전달해도 되며, 도구가 하이픈을 제거해 10자리 숫자로 정규화한다.
   - 도구 결과의 `status`, `business_number`, `input_value`, `total_count`, `records`를 그대로 판정에 사용한다.
   - `records`에는 `company_name`, `lab_name`, `scale`, `research_field`, `lab_type`이 포함된다.
2. `search_rnd_lab`이 연결되어 있지 않은 경우에만 브라우저 자동화가 가능한 다른 도구를 사용한다.
3. 일반 웹검색이나 `s_custsuno1` 쿼리 문자열을 붙인 URL 호출만으로는 공식조회 완료로 보지 않는다.
4. `search_rnd_lab`이 설치되지 않은 상태를 `rnd.or.kr 검색 0건`이나 `미등록`으로 표현하지 않는다. 이 경우 상태를 `MCP 미연결`로 표시한다.

## rnd.or.kr 실제 페이지 구조
공식 URL:
https://www.rnd.or.kr/user/infoservice/search5.do

사업자번호 입력 요소:
```html
<div class="f__control hyphen">
    <input type="text" class="c__input" id="s_custsuno1" name="s_custsuno1"
           value="1901382804" size="20" maxlength="10" placeholder="000-00-00000">
</div>
```

브라우저 자동화 시:
- selector: `input#s_custsuno1[name="s_custsuno1"]`
- `maxlength="10"`이므로 하이픈 없는 숫자 10자리만 입력한다.
- 기존 value를 지운 뒤 새 번호를 입력한다.
- 입력 후 실제 value가 요청번호와 같은지 검증한다.
- 검색 버튼 `검색하기`를 실제 클릭한다.
- 결과표의 `기업명 / 연구소·전담부서명 / 규모 / 연구분야 / 구분`을 읽는다.

GitHub 저장소의 `rnd_tax_checker/rnd_or_kr.py`와 `mcp_server.py`에는 이 절차를 Playwright 및 STDIO MCP `search_rnd_lab`으로 구현해 두었다.

## search_rnd_lab 결과 판정
- `confirmed`: 사업자번호 검색 실행 후 1건 이상 확인 → `공식 확인`
- `zero_results`: 실제 검색 실행 결과 0건 → `공식 검색 0건`
- `input_value_failed`: 입력값 설정 실패
- `input_not_found`: 사이트 입력 DOM 변경 가능성
- `search_control_not_found`: 검색버튼/폼 구조 변경 가능성
- `browser_dependency_missing`: 로컬 MCP 런타임에 Playwright/Chromium 설치 필요
- `execution_error`: 실행 오류. 오류 내용을 그대로 요약하고 공식 등록 여부는 보류

## 중요: URL 직접호출 실패를 조회 실패로 혼동하지 않기
`https://www.rnd.or.kr/user/infoservice/search5.do?s_custsuno1=...` 형태의 URL이 일반 웹 도구에서 열리지 않더라도, MCP `search_rnd_lab`이 사용 가능하면 URL 방식으로 재시도하지 말고 MCP를 호출한다. URL 직접호출 오류를 `직접검색 실행 불가`라고 최종 표시하지 않는다.

## 판정 문구
- 동일 법인 자체 사업장/연구소: "외부 위탁기관 판정 대상 아님 — 내부 연구개발비/비용배부 여부 별도 검토"
- 공식 등록 + 별표6 기관유형 + 실제 용역범위까지 직접 확인: "요건 충족 근거가 확인됨"
- 기관유형은 유력하나 KSIC/인정범위/실제 수행업무 일부 미확인: "적격 가능성이 있으나 추가확인 필요"
- rnd.or.kr 사업자번호 직접조회 0건: "rnd.or.kr 사업자번호 공식 검색 0건 — 미보유로 단정하지 않음"
- MCP가 아직 호스트에 연결되지 않음: "rnd.or.kr 조회용 MCP 미연결 — 공식 등록 여부 판단 보류"
- 입력/실행 오류: "rnd.or.kr 자동조회 오류 — 공식 등록 여부 판단 보류"
- 핵심 등록정보 확인 불가: "현재 공개자료만으로는 판단 보류"
- 확인된 사실이 별표6 유형과 명백히 불일치: "확인된 범위에서는 해당 경로 적용이 어려움"

세액공제 가능 여부를 법적 확정판정처럼 표현하지 않는다.
