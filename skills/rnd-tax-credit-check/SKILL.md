사용자가 사업자등록번호나 시험기관명을 주고 연구개발비 세액공제 적격 여부를 물으면 이 워크플로우를 사용한다.

## 사업자번호 정규화
- 사용자가 `353-88-00727`, `3538800727`, 공백이 섞인 형태 등으로 입력해도 검색 전 숫자가 아닌 문자를 모두 제거한다.
- 정규화 결과는 반드시 숫자 10자리여야 한다.
- rnd.or.kr에는 하이픈 없이 `3538800727`처럼 숫자 10자리만 전송한다.
- 사용자 응답에는 필요하면 `353-88-00727`처럼 다시 표시해도 되지만, 공식 검색값은 숫자 10자리로 표시한다.

## 0. 거래관계 먼저 구분
해당 사업자번호가 사용자의 자기 회사 본점·지점·사업장·연구소인지, 외부 제3자 시험/연구기관인지 우선 구분한다.
- 동일 법인 내부면 외부 위탁기관 판정 대상이 아니다.
- 계열사라면 별도 법인인지 확인한다.

## 기본 원칙
1. 최신 법령과 공식 등록현황을 우선 확인한다.
2. 사업자번호만 주어진 경우 먼저 현재 기관명을 식별한다.
3. 민간 기업정보는 기관명 식별 보조용으로만 사용한다.
4. 전문연구사업자, KSIC, KOLAS, 기업부설연구소/전담부서를 각각 분리해 확인한다.
5. 기관 적격성과 해당 비용 자체의 R&D 해당 여부는 별도로 판단한다.

## rnd.or.kr 공식조회 — POST 방식 우선
공식 검색 URL:
`https://www.rnd.or.kr/user/infoservice/search5.do`

사용자가 제공한 개발자도구 Network 정보에 따라 이 페이지는 검색 시 `POST` 요청을 사용한다.

### 검색 절차
1. 사용자 입력에서 하이픈·공백 등 숫자가 아닌 문자를 제거해 10자리 숫자로 만든다.
2. `search5.do`를 먼저 GET하여 세션/쿠키를 확보한다.
3. 같은 URL로 `application/x-www-form-urlencoded` POST를 전송한다.
4. 핵심 Form Data는 다음과 같다.
   - `currentPage=1`
   - `s_yngugubn=3`
   - `save_s_yngugubn=3`
   - `excel_yn=N`
   - `s_type=CUSTNAME`
   - `s_custsuno1=<정규화된 숫자 10자리>`
   - `save_s_custsuno1=<정규화된 숫자 10자리>`
5. 응답 HTML에서 결과표를 찾아 `기업명 / 연구소·전담부서명 / 규모 / 연구분야 / 구분`을 추출한다.
6. POST 직접조회가 네트워크/세션 문제로 실패한 경우에만 Playwright 브라우저 자동화를 fallback으로 사용한다.

### 구현 우선순위
- 호스트에 `search_rnd_lab` 도구가 있으면 반드시 우선 호출한다.
- `search_rnd_lab` 구현은 POST 직접조회 우선, Playwright fallback이어야 한다.
- 단순히 URL에 `?s_custsuno1=`를 붙이는 GET 방식은 공식 조회로 간주하지 않는다.

## rnd.or.kr 페이지 DOM fallback
사업자번호 input:
`input#s_custsuno1[name="s_custsuno1"]`

브라우저 fallback에서는:
- 기존 값을 지운다.
- 하이픈 없는 숫자 10자리를 입력한다.
- 실제 input value가 요청번호와 같은지 검증한다.
- `검색하기` 버튼을 클릭한다.
- 결과표를 파싱한다.

## search_rnd_lab 결과 판정
- `confirmed`: 실제 POST/브라우저 검색 후 1건 이상 확인 → 공식 확인
- `zero_results`: 실제 검색 실행 결과 0건 → 공식 검색 0건
- `http_execution_error`: POST 직접조회 오류. 브라우저 fallback 결과를 확인한다.
- `input_value_failed`, `input_not_found`, `search_control_not_found`, `execution_error`: 자동조회 오류
- 도구 자체가 연결되어 있지 않으면 `MCP/API 미연결`로 표시하고 미등록으로 단정하지 않는다.
