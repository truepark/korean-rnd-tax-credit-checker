사용자가 사업자등록번호나 시험기관명을 주고 연구개발비 세액공제 적격 여부를 물으면 이 워크플로우를 사용한다.

## 0. 거래관계 먼저 구분
가장 먼저 해당 사업자번호가 사용자의 자기 회사 본점·지점·사업장·연구소인지, 아니면 외부 제3자 시험/연구기관인지 구분한다.
- 자기 회사의 본점·지점·사업장·R&D센터라면 이를 별표6상 외부 위탁기관으로 곧바로 보지 않는다.
- 같은 법인 내 사업장 간 비용배부, 내부 시험, 내부 연구는 외부 위탁비 검토와 별개의 문제로 표시한다.
- 계열사·관계사라면 법인이 다른지, 계약 및 세금계산서 발행 주체가 누구인지 확인한다.
- 거래관계가 불명확하면 최종 판정 전에 사용자에게 귀사 자체 사업장인지 / 외부 업체인지 확인이 필요하다고 표시한다.

## 기본 원칙
1. 최신 법령과 공식 등록현황을 우선 확인한다.
2. 사업자번호만 주어진 경우 먼저 현재 기관명과 동일 법인 여부를 식별한다.
3. 민간 기업정보는 기관명 식별 보조용으로만 사용하고 적격 판단의 핵심 근거로 사용하지 않는다.
4. 국가법령정보센터에서 적용 사업연도의 조세특례제한법 시행령 제9조 및 별표6을 확인한다.
5. 전문연구사업자, KSIC 기술시험·검사 및 분석업, KOLAS 현재 인정상태·인정범위, 기업부설연구소 정보를 각각 분리해 확인한다.
6. KOLAS 인정만으로 별표6 적격을 확정하지 않는다.
7. 기업부설연구소/연구개발전담부서의 공식 확인은 반드시 기업부설연구소/전담부서 신고관리시스템의 공식 검색 페이지를 우선 사용한다.
8. 기업부설연구소 보유만으로 외부 수탁기관 적격을 확정하지 않는다.
9. 외부기관 적격성과 해당 시험비 자체가 연구개발비인지 여부를 분리해서 판단한다.

## 조회 순서
1. 사업자번호/기관 식별 및 동일 법인 여부 확인
2. 거래관계 판정: 외부 제3자 / 동일 법인 내부 / 계열사 / 불명확
3. 적용 사업연도의 별표6 확인
4. 전문연구사업자 확인
5. KSIC 확인
6. KOLAS 인정상태·인정범위 확인
7. 기업부설연구소/연구개발전담부서 공식 확인

## 기업부설연구소/연구개발전담부서 공식 확인 절차
공식 확인 URL:
https://www.rnd.or.kr/user/infoservice/search5.do

### 사업자번호 입력 요소의 실제 HTML 계약
rnd.or.kr 사업자번호 입력란은 다음 구조를 사용한다.

```html
<div class="f__control hyphen">
    <input type="text" class="c__input" id="s_custsuno1" name="s_custsuno1"
           value="1901382804" size="20" maxlength="10" placeholder="000-00-00000">
</div>
```

따라서 자동화에서는 다음을 반드시 지킨다.
- 입력 요소는 `input#s_custsuno1[name="s_custsuno1"]`로 찾는다.
- `maxlength="10"`이므로 **하이픈 없는 숫자 10자리**만 입력한다. `119-86-83629`처럼 하이픈을 포함해 입력하지 않는다.
- placeholder에 하이픈 형식이 보이더라도 실제 DOM value는 숫자 10자리다.
- 페이지에 기존 value가 남아 있을 수 있으므로 반드시 `clear/fill` 또는 이에 준하는 방식으로 기존 값을 완전히 덮어쓴다.
- 입력 후 실제 element value가 요청한 10자리와 일치하는지 검증한 뒤 검색을 실행한다.
- 사이트 JavaScript가 input/change 이벤트를 감지할 수 있으므로 브라우저 자동화에서는 입력 후 `input`, `change`, 필요 시 `blur` 이벤트가 발생하도록 한다.

### 사업자번호 직접 조회를 우선 실행
1. 사용자가 입력한 사업자번호에서 하이픈과 공백을 제거해 숫자 10자리로 정규화한다.
2. rnd.or.kr `연구소/전담부서 검색` 페이지를 연다.
3. `input#s_custsuno1[name="s_custsuno1"]`에 정규화된 숫자 10자리를 직접 입력한다.
4. 입력 직후 `value`를 다시 읽어 요청번호와 동일한지 확인한다. 다르면 검색하지 말고 입력 실패로 처리한다.
5. 검색 버튼을 실제 클릭하거나 해당 검색 form을 submit하여 조회를 실행한다.
6. 결과 테이블 또는 결과 건수가 변경될 때까지 기다린다.
7. URL에 `s_custsuno1` 쿼리파라미터만 붙이는 방식은 보조수단으로만 사용한다.
8. 검색 결과 화면에 나온 값을 그대로 읽어서 사용자 응답에 다시 표시한다.
9. 결과가 1건 이상이면 조회 사업자번호, 기업명, 연구소/전담부서명, 규모, 연구분야, 구분, 조회일을 표시한다.
10. 사업자번호 검색 결과가 0건일 때만 기업명으로 보조 검색한다.
11. 기업명 보조 검색 결과가 있더라도 사업자번호 동일성이 확인되지 않으면 `공식 확인`으로 판정하지 않는다.

### 브라우저 자동화 구현 시 권장 순서
```python
page.goto("https://www.rnd.or.kr/user/infoservice/search5.do")
input_box = page.locator('input#s_custsuno1[name="s_custsuno1"]')
input_box.fill("1198683629")
assert input_box.input_value() == "1198683629"
# 사이트의 실제 검색 버튼을 클릭하거나 검색 form submit
page.get_by_text("검색").click()
# 결과 테이블/건수 갱신 대기 후 파싱
```

`fill()`이 사이트 스크립트와 충돌하는 경우 다음 순서로 보조 처리한다.
- focus
- 기존 값 전체 선택 후 삭제
- 숫자 10자리 입력
- `input`/`change` 이벤트 발생
- blur
- value 재검증
- 검색 실행

### 조회 실행 상태를 반드시 구분
rnd.or.kr 조회 결과는 다음 네 상태를 구분해서 표시한다.
- `공식 확인`: 사업자번호를 실제 입력하고 검색을 실행하여 일치 결과가 확인됨
- `공식 검색 0건`: 사업자번호를 실제 입력하고 검색을 실행했으나 결과가 0건임
- `입력값 설정 실패`: `#s_custsuno1`은 찾았지만 실제 value가 요청한 사업자번호로 설정되지 않음
- `직접검색 실행 불가`: 현재 사용 가능한 도구가 DOM 입력/검색버튼 클릭/세션/동적 결과 파싱 등을 실행하지 못해 실제 검색 자체를 완료하지 못함

`직접검색 실행 불가` 또는 `입력값 설정 실패`를 `공식 검색 0건`, `미보유`, `미등록`으로 해석하지 않는다.

## 판정 문구
- 동일 법인 자체 사업장/연구소: "외부 위탁기관 판정 대상 아님 — 내부 연구개발비/비용배부 여부 별도 검토"
- 공식 등록 + 별표6 기관유형 + 실제 용역범위까지 직접 확인: "요건 충족 근거가 확인됨"
- 기관유형은 유력하나 KSIC/인정범위/실제 수행업무 일부 미확인: "적격 가능성이 있으나 추가확인 필요"
- rnd.or.kr 사업자번호 직접조회 0건: "rnd.or.kr 사업자번호 공식 검색 0건 — 미보유로 단정하지 않음"
- rnd.or.kr 입력값 설정 실패: "rnd.or.kr 사업자번호 입력 실패 — 공식 등록 여부 판단 보류"
- rnd.or.kr 검색 자체를 실행하지 못함: "rnd.or.kr 직접검색 실행 불가 — 공식 등록 여부 판단 보류"
- 핵심 등록정보 확인 불가: "현재 공개자료만으로는 판단 보류"
- 확인된 사실이 별표6 유형과 명백히 불일치: "확인된 범위에서는 해당 경로 적용이 어려움"

세액공제 가능 여부를 법적 확정판정처럼 표현하지 않는다.
